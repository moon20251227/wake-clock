# 醒刻 · 体感时钟

把「现在」换算成「身体觉得现在几点」，帮你感知清醒程度、看到漂移、并逐步把作息拉回目标。

适合：作息混乱、常熬通宵、一天睡多次、傍晚补觉的人。**不是医疗诊断**，只是基于睡眠记录的体感估算。

## 核心逻辑

- **体感时钟 E**：醒着时体感每小时走 1 格；睡着时每睡 1 小时往回拨 2 格（最低回到满血）。E 恢复是累计的——几次睡眠加起来睡够约 7h 也能回 0。
- **校准点自校准**：每次 E 回到 0（睡够了），表盘自动对到当时实际几点。无需手动设置基准起床。
- **24h 双针表盘**：白针=实际时间，紫针=体感时间，中间弧=漂移量，外圈颜色=状态。
- **等级**（纯描述，无任何科学换算）：E<16h 正常 / 16–20 疲劳 / 20–24 很累 / ≥24 极限。
- **最近24h睡眠**：只统计完整结束在 24h 内的睡眠块，不截断。
- **校准建议**：偏离量 + 具体处方（现在睡到目标起床能否一次归位，不能就给分步方案），另有两个交互按钮「有点困」「想调回正常」。
- **统计不用日历零点**（你的零点被熬夜拉通了）：睡眠量用滚动 24h；节律图的行只是视觉网格 + 补记入口。

## 使用

1. 打开页面 → 记一笔最近的睡眠（或直接点「睡下了」/「醒来了」打点）。
2. 表盘开始走动。睡前点「睡下了」，醒来点「醒来了」，最省事。
3. 忘了记？去**趋势**页点节律图的某一行，可补记那一天。
4. 设置里可改：目标作息（默认 1:00 睡 / 8:00 起）、理想睡眠（默认 7h）、体感针颜色、等级阈值。
5. 数据只存本机 localStorage；设置里可导出/导入 JSON 备份。

## 本地运行

```bash
cd D:\wake-clock
py -m http.server 8000
# 手机同一局域网访问 http://<电脑IP>:8000 可加到主屏幕（需 HTTPS 才能完整 PWA，见下）
```

**直接双击 `index.html` 也能完整使用**（时间输入是文本格式，不依赖 Chrome 在 `file://` 下失效的原生选择器，如 `08-05 22:00`；触摸设备会自动升级回原生选择器）。但**手机离线/添加到主屏幕需要走服务器或部署**（见下），页面顶部在 `file://` 下会显示提醒横幅。

## 部署为 PWA（手机离线可用）

用之前那套：推到 GitHub Pages + 自定义 `.asia` 域名（HTTPS 才能注册 Service Worker、支持「添加到主屏幕」离线打开）。

推仓库时确保提交 `index.html`、`sw.js`、`manifest.webmanifest`、`icons/` 全部文件。页面请求是「网络优先」策略——改了代码，用户刷新就能看到新版，不用手动清缓存；只有改了 `manifest`/`icons` 才需要把 `sw.js` 顶部的 `CACHE` 版本号 +1 强制整体换新。

## 测试

`tools/run-core-test.ps1` 用 cscript 跑三组检查：核心算法（对照讨论时验证过的表格数据）、整脚本语法、DOM 冒烟（全部渲染/记录/建议路径）。改动核心逻辑后跑一遍：

```powershell
powershell -ExecutionPolicy Bypass -File D:\wake-clock\tools\run-core-test.ps1
```

（`index.html` 的 `// ===CORE-START===` / `// ===CORE-END===` 之间是核心算法，测试直接从单文件提取，无重复实现。）

## 文件

- `index.html` — 整个应用（单文件，无框架、无图表库）
- `sw.js` — 离线缓存 Service Worker
- `manifest.webmanifest` — PWA 清单
- `icons/` — 应用图标
- `tools/` — 图标生成脚本、测试脚本
